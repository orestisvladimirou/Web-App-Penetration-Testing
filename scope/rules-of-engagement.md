# Rules of Engagement and Scope

**Assessment:** OWASP Juice Shop — authorized local training environment  
**Assessment date:** 30 October 2026 (ongoing)  
**Status:** Educational self-assessment; not a third-party engagement

## Authorization

The tester owns and operates the intentionally vulnerable OWASP Juice Shop Docker container on the local Windows 11 workstation. Testing is limited to this explicitly authorized training target. No authorization is claimed for any external systems.

## In scope

- Web application accessible at `http://localhost:3000` and application paths on that same origin
- Requests generated by normal browsing, authentication experiments, and controlled manual tests
- Passive traffic inspection using OWASP ZAP
- Local API endpoints served by the Juice Shop instance

## Out of scope

- Google Chrome autofill and password-check services, including `*.googleapis.com`
- Third-party websites, CDNs, APIs, and unrelated local services
- Any external Juice Shop demo deployment
- Host operating-system exploitation, Docker escape, denial-of-service, destructive testing, or password spraying against real accounts

## Safeguards

1. Bind the container port to loopback: `127.0.0.1:3000:3000`.
2. Set an exact ZAP context inclusion regex: `^http://localhost:3000(?:/.*)?$`.
3. Enable **Protected Mode** and verify only the local context is in scope before active scanning.
4. Use disposable lab-only accounts; never reuse personal credentials.
5. Prefer minimally invasive proof of impact; stop once exploitation is demonstrated.
6. Do not commit raw HTTP archives, cookies, JWTs, passwords, personal information, or unredacted screenshots.
7. Save relevant tool versions, timestamps, request/response metadata and negative-control results.

## Constraints and limitations

- This is a deliberately insecure **training application**. Findings are not evidence of flaws in a production business service.
- Current findings are from manual inspection of a local instance; application version/image digest has not yet been recorded.
- No destructive exploitation, persistence, or data exfiltration is within scope.
- An automated scanner alert is not considered a confirmed vulnerability until evidence and impact are reviewed.

## Stop conditions

Stop testing if the target is no longer local, requests unexpectedly reach an external host, the container stops behaving as expected, or testing risks affecting unrelated systems.
